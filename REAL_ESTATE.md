# 🇷🇸 Сербия 24 — недвижимость, продажа и аренда

Это независимый сценарий в существующем репозитории новостного Telegram-бота.

## Что делает
- Проверяет предложения продажи квартир и домов, а также недорогую аренду квартир в 7 городах Сербии. Проверяет по два города в час, с ротацией.
- Первая версия: минимальные факты из публичных страниц 4zida и ссылка на оригинал; без копирования фотографий и полных описаний.
- Отбирает по верхним пределам цен и сравнивает €/м² с небольшой выборкой объявлений того же города и типа объекта. Результат — предварительный, **не оценка рыночной цены**.
- Публикует не более одного объявления в час с 08:00 до 22:00 по Белграду.
- Не повторяет уже опубликованные ссылки. Не публикует предложения, обновлённые более 14 дней назад.
- Не объявляет собственника подтверждённым; статус определяется только по опубликованной информации. Легальность объекта и наличие в продаже не подтверждены.

## Подключение
1. Создайте группу (или канал), проверьте её публичный адрес. @Serbia24Dom пока лишь предложен, доступность не проверена.
2. Добавьте нового Telegram-бота с правом публиковать сообщения.
3. В GitHub: Settings → Secrets and variables → Actions → Secrets → New repository secret. Название PROPERTY_BOT_TOKEN, значение — токен нового бота из @BotFather. Ранее опубликованный в чате токен лучше заменить.
4. Там же откройте Variables → New repository variable: PROPERTY_CHAT_ID. Вставьте настоящий @username группы (или числовой ID чата вида -100...).
5. Только после разрешения источника включите Variables → PROPERTY_ENABLE_4ZIDA = 1. Иначе мониторинг публичного сайта не запускается.
6. В Actions запустите Serbia24 real estate → Run workflow. Потом поиск будет запускаться каждый час.
7. Если одного из этих параметров нет, публикации не будет. Новостной бот продолжит работать отдельно.

## Важно
Правила 4zida ограничивают использование контента. Прежде чем включать регулярный публичный сбор, нужно согласовать разрешение с площадкой или заменить источник на разрешённый API/feed; никогда не обходите robots.txt, ограничения доступа или капчу. Даже открытые объявления могут оказаться устаревшими, ошибочными или с комиссией — эти условия нужно проверять у продавца.

Расширения: разрешённые источники, снижение цены, точное сравнение по районам, объявления от собственников с модерацией, фотографии с разрешения владельца.

## Новый формат публикации: фотогалерея и разбор на русском

Одна публикация содержит: тип (покупка/аренда), город и район, цену в евро (для аренды — в месяц), площадь и €/м², описание на русском, подтверждаемые плюсы, минусы или пункты для уточнения, тип продавца, дату обновления и ссылку на оригинал. Оценка выгодности — предварительная, а не гарантия. Если фактов для плюсов и минусов нет, бот пишет «не подтверждены» или «не указаны», не выдумывая их.

До пяти фото публикуются в Telegram альбомом только при отдельном разрешении правообладателя. Сначала публикуется текст, затем фотографии ответом на него; сбой загрузки фото не удаляет карточку со ссылкой. Фото чужих объявлений, включая 4zida, по умолчанию не публикуются.

### Публикация объявлений от собственников и агентств

В репозитории создан файл data/estate_submissions.json. В нём находится специально выключенный пример, который нельзя выдавать за реальное объявление.

Для настоящего объявления обязательны: approved: true, permission_to_publish: true, подлинная ссылка url (https), city, kind (prodaja-stanova, izdavanje-stanova, prodaja-kuca), title, price_eur, area_m2, updated (YYYY-MM-DD). Дополнительно можно передать location, description_ru, pros, cons, advertiser и photo_urls.

Если фотографиями владеет отправитель или имеется документированное разрешение на републикацию в Telegram, добавьте photo_permission: true и прямые HTTPS-ссылки на изображения в photo_urls. Согласия храните за пределами общедоступного репозитория; не размещайте личные документы и телефоны без разрешения.

Для лицензированного использования фотографий 4zida необходимы два независимых разрешения в конфигурации: PROPERTY_ENABLE_4ZIDA=1 на источник и PROPERTY_4ZIDA_MEDIA_LICENSED=1 отдельно на фотографии. Не ставьте эти параметры без реальных прав использования.

Автоматический поиск на 4zida по умолчанию выключен, а пример заявки неактивен. Для непрерывного автоматического потока реальных предложений потребуется разрешённый источник или официальный feed/API.

## Партнёрские JSON-фиды: без скрапинга чужих площадок

Добавлен отдельный модуль partner_feeds.py. Он запрашивает HTTPS-фиды только у партнёров, предоставивших разрешение на публикацию объявлений в Telegram. Ссылки на чужие общедоступные сайты без разрешения сюда не подходят; открытый REST API не равен лицензии на копирование фотографий и описаний.

Для запуска с подписанным партнёром в Settings → Secrets and variables → Actions → Variables задайте:
- PROPERTY_PARTNER_FEEDS_ENABLED = 1
- PROPERTY_PARTNER_LICENSE_CONFIRMED = 1 — только после получения подтверждённых прав.
- PROPERTY_PARTNER_FEEDS = https://agency.example.org/feed.json — реальный URL JSON-фида; до 5 URL через запятую.

Если партнёр требует Bearer-токен, добавьте Actions → Secrets: PROPERTY_PARTNER_FEED_TOKEN. URL и ключ от разных партнёров с разными полномочиями лучше хранить в отдельных проектах: одна настройка токена применяется ко всем URL в данном списке. Не публикуйте токены в коде.

JSON-фид должен содержать объект с массивом listings. Пример одного **условного** объявления (не является реальным объектом):

```json
{
  "listings": [
    {
      "approved": true,
      "permission_to_publish": true,
      "url": "https://agency.example.org/listings/123",
      "city": "Панчево",
      "kind": "izdavanje-stanova",
      "title": "Квартира с одной спальней",
      "price_eur": 260,
      "area_m2": 41,
      "updated": "2026-11-13",
      "advertiser": "Агентство",
      "location": "Панчево, центральный район",
      "description_ru": "Квартира в аренду; характеристики уточняются.",
      "pros": ["Хорошая стоимость"],
      "cons": ["Комиссия не указана"],
      "photo_permission": true,
      "photo_urls": ["https://agency.example.org/media/123/1.jpg"]
    }
  ]
}
```

Свойства approved и permission_to_publish должны отражать реальные права партнёра и одобрение к публикации. Дополнительное photo_permission=true означает, что владелец фотографий разрешил публикацию **в нашем Telegram**, а не только на собственном портале. Для включённых фидов выполняется ежечасный поиск без дубликатов; сообщение на русском, альбом до пяти разрешённых фотографий, ссылка на оригинал. Отсутствие фидов/разрешений приводит к нулю новых постов, а не к выдуманным объявлениям.

Возможные поставщики для переговоров: Riael (partners@riael.com; API для партнёров) и агентства с собственными экспортами XML/JSON. PlusHouse не охватывает Сербию, хотя имеет открытый API; Markondo выдаёт API-ключ по заявке и ориентирован на новостройки. Подключение к этим сервисам не означает, что получены ключи или разрешения на изображения.
